# Видео — TASK-057 / FR-075

После подготовки пакета откройте «Видео WebM / MP4». Размеры 640×360, 1280×720 или 1920×1080, 24/25/30/60 FPS, 1–30 секунд. WebM использует VP9, MP4 — H.264; доступность проверяется для выбранного размера и FPS. Нет звуковой дорожки. Длительность округляется до целого числа кадров. Результат остаётся в RAM до явного скачивания; проект и история не меняются.

Общий `TriadRuntime` загружает ресурсы и дожидается декодирования цветовых/PBR-карт, затем рендерит каждый кадр в точное время `index/fps`. Масштаб экрана не меняет выходное разрешение. CanvasSource из Mediabunny 1.65.2 передаёт кадры с duration `1/fps`, с ожиданием обратного давления кодировщика; контейнер собирается в памяти. Ограничения размеров и длительности ограничивают объём работы. Кодировщик загружается отдельным chunk. Отмена закрывает encoder/output, размонтирует renderer и освобождает URL ресурсов.

Записывается первый/default clip с его loop-настройкой и настроенными instance overrides; временные interaction rules вычисляются последовательно. Физика отключена, поскольку не поддерживает произвольное controlled time. События мыши/клика не записываются. Видео использует сценовую камеру и растровый WebGL2 backend TSX-runtime; это не запись свободной редакторской камеры и не path tracing. UI явно сообщает эти ограничения.

## Матрица

| Возможность | Поведение |
|---|---|
| WebCodecs VP9 | Покадровый WebM, если canEncodeVideo подтвердил конфигурацию |
| WebCodecs AVC | Условный MP4, та же проверка |
| MediaRecorder WebM | Показывается диагностика; не используется для обещания точного FPS |
| Нет кодека | Ошибка с альтернативами: WebM, браузер с WebCodecs или TSX/ZIP |
| FFmpeg WASM | Отдельный эксперимент `qa/video`; не включён в основной bundle |

## Проверки

`qa/video-animation.triad3d`: синий куб поднимается в двухсекундном цикле. Встроенный Chromium под Windows подтвердил VP9 и AVC. Реальные скачанные файлы проверены ffprobe: оба 640×360, 300 кадров, 30/1 FPS, 10.000000 с. WebM — 248402 байта; MP4 — 216406 байт. Кадры `qa/video-frame-0.png` и `qa/video-frame-1.png` подтверждают изменение позиции. Отмена повторного 1080p-рендера вернула управление без файла (`qa/video-export-cancel.png`); новых console errors после исправления ключей React нет.

Тесты проверяют точную последовательность временных меток, отмену до следующего кадра и недопустимые параметры. Сборки полного TSX-runtime повторяются, поскольку подготовка текстур и render loop общие с экспортом.

Источники API: [Mediabunny CanvasSource](https://mediabunny.dev/guide/media-sources), [создание и отмена Output](https://mediabunny.dev/guide/writing-media-files), [официальный FFmpeg WASM overview](https://github.com/ffmpegwasm/ffmpeg.wasm/blob/main/apps/website/docs/overview.md). Mediabunny поставляется по MPL-2.0; исходники зависимости не изменены.

## FFmpeg WASM: решение по эксперименту

`qa/video` фиксирует @ffmpeg/ffmpeg 0.12.15 и single-thread @ffmpeg/core 0.12.10. В Chromium 157 / Windows без cross-origin isolation и SharedArrayBuffer загрузка заняла 535 мс, кодирование testsrc 640×360/30 FPS/10 с — 3596 мс; файл 218827 байт. Независимый ffprobe подтвердил H.264, 300 кадров и 10.000000 с. Доказательства: `qa/video-ffmpeg-profile.json`, `qa/video-ffmpeg.png`. Это проверка WASM-кодировщика на синтетическом источнике, не готовый fallback для timeline-кадров.

Решение: основной экспорт использует WebCodecs; автоматический FFmpeg fallback не включать. Single-thread core технически работает на обычном static host, но добавляет 32 232 419 байт WASM и промежуточные кадры в память; для промышленной интеграции нужен отдельный ограниченный конвейер передачи кадров. При недоступном кодеке текущий продукт показывает альтернативу, как требует FR-075. В эксперименте кнопка отмены завершает Worker. Core имеет GPL-2.0-or-later и остаётся отдельной QA-зависимостью, не попадает в приложение или TSX-пакеты.

Регрессии ревью: служебный `__triadCapture` не пересекается с пользовательскими именами props; чистый TSX harness проверяет параметр `capture`. Preview и видео используют общую карту defaults с ID развёрнутых экземпляров. Браузерный экспорт с `capture=2` и белым default color дал увеличенный белый куб (`qa/video-frame-props.png`, `qa/video-export-props.png`), 300 кадров / 10 с; без новых ошибок runtime. Тест readiness дожидается двух отложенных bitmap и проверяет освобождение обоих.
